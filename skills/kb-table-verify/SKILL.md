# kb-table-verify — 변환 표 시각 대조

PDF를 Markdown으로 바꿀 때(tools/pdf2md.py, docling) 병합 셀·다단 행 제목이 있는 표는 구조가 틀어질 수 있다.
단어 대조(pdf2md 원문 대조)와 docling 경고는 **단어가 빠진 경우**만 잡고, **단어는 다 있는데 위치만 틀어진 경우**는 못 잡는다.
이 스킬은 원본 PDF 페이지를 **이미지로 보고** 표 구조를 대조한다.

## 도구 위치
legal-answer 스킬과 같다. 저장소 루트 = `COMPLIANCE_AI_HOME`(미설정이면 `$HOME/workspace/law-assist`).
원본 PDF는 `data/kb_src/<문서>.pdf`, 변환본은 같은 이름의 `.md`.

## 언제 쓰나
| 상황 | 대상 쪽 | 결과물 |
|---|---|---|
| **답변 중** — 검색 결과에 `⚠️ 표 구조 확인 필요`가 붙은 청크, 또는 표 값을 근거로 인용하려 할 때 | 그 청크의 쪽 | 답변에만 반영(지식베이스는 고치지 않음) |
| **인그레스트 직후 검수** — kb_add·pdf2md가 `표 셀 누락 N쪽: [...]`을 출력했을 때 | `.report.json`의 `table_warnings` 쪽 (+ `issues` 중 표가 있는 쪽) | 교정본을 kb_fix.py로 반영 |

모든 표를 다 보지 않는다(이미지 비용). 경고가 붙은 쪽, 그리고 답변에 실제로 인용할 표만 본다.

## 1. 페이지를 이미지로 본다 — 쓸 수 있는 수단을 위에서부터
1. **Read 도구로 PDF 쪽 직접 읽기**: `Read(file_path=<pdf>, pages="96")`. poppler(`pdftoppm`)가 Claude Code 프로세스 PATH에 있어야 한다. 기준 수단.
2. **pdftoppm 명령으로 PNG 생성 후 Read**: `pdftoppm -f 96 -l 96 -png -r 110 <pdf> <스크래치패드>/page` → `page-096.png`를 Read.
   poppler를 설치한 직후라 Claude Code가 옛 PATH를 쓰고 있으면 1번은 실패한다. 이때 셸에서 PATH만 다시 읽어 실행하면 된다(Windows: 사용자 PATH의 poppler `Library\bin`을 추가).
3. **Python으로 렌더링 후 Read**: docling을 설치했다면 `pypdfium2`가 함께 있다.
   `python -c "import pypdfium2 as p; p.PdfDocument('<pdf>')[95].render(scale=1.6).to_pil().save('<png>')"` (쪽 인덱스는 0부터).
4. **수단이 없으면 시각 대조를 하지 않는다.** `rag.py show --collection <이름> --page <쪽> --raw`로 원본 텍스트만 대조하고,
   **검색 결과의 경고 문구를 사용자에게 그대로 알린다**("이 표는 변환 중 셀이 버려져 구조를 확인하지 못했습니다 — 원본 PDF p.N 확인 필요").
   그 표에서 행·열 짝이 필요한 값은 "(미검증)"으로 둔다. poppler 설치를 안내해도 된다(Windows: `winget install oschwartz10612.Poppler`).

## 2. 대조한다
- 변환본: `rag.py show --collection <이름> --page <쪽>` (경고·교정 표시 포함)
- 원본 텍스트: 같은 명령에 `--raw` — 이미지에서 읽은 글자를 원본 텍스트로 재확인할 때.
- 판정은 셋 중 하나:
  - **일치** — 행·열 짝과 값이 같다.
  - **구조 오류** — 값은 다 있으나 묶음 셀·행 제목이 다른 행에 붙거나 빠짐, 표 제목이 셀에 섞임 등.
  - **값 오류** — 값이 빠지거나 다른 칸에 들어감.

## 3-A. 답변 중이면
- 지식베이스는 고치지 않는다. 이미지로 확인한 행·열 짝으로 답하고, 근거에 **"원본 PDF p.N 시각 대조"**를 적는다.
- 구조 오류·값 오류였다면 답변 끝에 한 줄로 알리고, 인그레스트 검수(3-B)를 제안한다.

## 3-B. 인그레스트 검수면 — 교정본 반영
1. 그 쪽 **전체**를 Markdown으로 다시 쓴다(쪽 표시 `<!-- p.N -->`와 경고 줄은 빼고 본문만). 표 앞뒤 문단도 원래 md 그대로 포함한다.
   - **문구는 원문 그대로**. 고치는 것은 표 구조뿐이다: 행·열 배치, 표 제목 위치.
   - 병합 셀은 md 표로 표현할 수 없으므로 **그 셀이 걸친 행마다 값을 반복**한다(docling과 같은 방식).
   - 이미지에만 있고 PDF 텍스트에 없는 글자(그림으로 된 "참고" 표시 등)는 넣지 않는다 — 다음 단계에서 거부된다.
2. 검사: `python3 tools/kb_fix.py <md> --page <쪽> --file <교정본> --check`
   - 교정본의 모든 단어가 원본 PDF 그 쪽 텍스트에 있어야 통과한다(띄어쓰기 무시). 원본에 없는 단어가 하나라도 있으면 거부.
3. 반영: 같은 명령에서 `--check` 대신 `--note "Claude 시각 대조(<수단>): <무엇을 고쳤나>"`.
   - md의 그 쪽이 교체되고 `<!-- corrected: … -->`가 남는다. 교정본은 `<문서>.fixes/p<쪽>.md`에 보관되어 pdf2md로 다시 변환해도 자동으로 다시 적용된다.
4. 재인덱싱: `python3 tools/rag.py ingest <md> --collection <이름> --append` (같은 문서라 교체됨).
   이후 검색·show 결과에 `✔ 교정된 쪽: …`이 표시된다.

## 항목 머리말 누락 (인그레스트 출력의 `⚠️ 항목 정합성 문제`)
변환이 항목 머리말 표를 깨뜨리면(예: `| 항 | 목 3.5.2 … |`처럼 칸이 잘못 나뉨) 그 항목이 인식되지 않고,
RAG 청크·관계가 **앞 항목에 잘못 붙는다**. `rag.py ingest`(관계 추출)가 번호 빈칸·'관련 법규' 칸 중복·기준 목록 불일치로 알려 준다.
단독 확인: `python3 tools/relations.py check <md>`.
1. 출력의 쪽 범위(예: "3.5.1(p.250)와 3.5.3(p.259) 사이")에서 빠진 항목의 머리말이 있는 쪽을 찾는다 — `rag.py show --page <쪽>`로 md를 보고, 필요하면 1번 수단으로 이미지 대조.
2. 그 쪽 md 전체를 교정본으로: 머리말 줄을 `| 항 목 | <번호> <항목명> |`로 고친다(문구는 그대로, 칸 구분만).
3. 위 3-B의 2~4단계(`kb_fix.py --check` → 반영 → `--append` 재인그레스트). 단어가 같으므로 검사를 통과한다.
4. 재인그레스트 출력이 `🔎 항목 정합성: … 없음`인지 확인.

## 금지
- 교정에서 문구·숫자를 바꾸거나 보충하기(구조만 고친다. kb_fix가 원본에 없는 단어를 거부하는 이유)
- 이미지를 보지 못했는데 "대조 완료"라고 쓰기 — 수단이 없으면 1-4대로 경고를 알린다
- 경고가 없는 쪽까지 일괄로 이미지 대조하기(비용). 필요한 쪽만
