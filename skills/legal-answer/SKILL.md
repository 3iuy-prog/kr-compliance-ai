# legal-answer — 표준 법률 답변 스킬

모든 법률/규제 답변을 일관된 근거 기반 형식으로 표준화한다.

## 도구 위치 (cwd 무관)

이 스킬은 홈(`~/.claude/skills/legal-answer` → 저장소 `skills/legal-answer` 심볼릭 링크)에 등록돼 어느 디렉터리에서든 쓰인다.
로컬 도구(`legalize.py` `crossmap.py` `rag.py` `kb_add.py`)는 ai-a3sc 저장소에 있고 `__file__` 기준으로 데이터를 찾으므로 **어디서 실행하든 절대경로로 호출**하면 된다.

- 저장소 루트 = 환경변수 `COMPLIANCE_AI_HOME`. 미설정이면 `$HOME/workspace/ai-a3sc`.
- Bash 호출 간 셸 변수가 유지되지 않으므로 **도구 명령마다 앞에** 다음을 붙인다:
  `COMPLIANCE_AI_HOME="${COMPLIANCE_AI_HOME:-$HOME/workspace/ai-a3sc}"; python3 "$COMPLIANCE_AI_HOME/tools/legalize.py" show 개인정보보호법 --jo 29`
- 아래 본문의 `python3 "$COMPLIANCE_AI_HOME/tools/…"` 표기는 모두 이 프리픽스를 전제로 한다.
- 저장소 경로가 없으면 로컬 도구 대신 법령 MCP만 쓰고, 그것도 없으면 "미확인".

## 실행 절차

1. **의도 분류** — 질의를 4개 중 하나로 라우팅:
   - `Q&A` 단순 규정 질의 → 근거 인용 답변
   - `MAPPING` 통제/인증기준 ↔ 법령 매핑 → 크로스매핑 표 포함
   - `AMENDMENT` 개정 영향 → legalize-kr Git diff 기반 변경 요약
   - `DIAGNOSIS` 문서 진단 → 관련 기준 매칭 + gap

2. **원문 조회 (필수)** — 답하기 전 근거를 실제로 조회한다. 기억으로 조문을 쓰지 않는다.
   - L1 법령 / L2 행정규칙: 법령 MCP(`korean-law-mcp`)로 조·항·호 조회. MCP 없으면 아래 로컬 도구 사용.
   - **로컬 대안(법령 원문)**: `python3 "$COMPLIANCE_AI_HOME/tools/legalize.py" show <법령> --jo <N>` (대상 5법). MCP·legalize 둘 다 없으면 "미확인".
   - L3 인증기준/점검항목: 정형화 데이터 `python3 "$COMPLIANCE_AI_HOME/tools/crossmap.py" isms <코드>` +
     원문 상세는 RAG `python3 "$COMPLIANCE_AI_HOME/tools/rag.py" search "<질의>" --collection <isms 등> -k 5`.
   - 조회 실패 시 → 해당 부분을 **"미확인"**으로 표기하고 단정하지 않는다.

### 의도별 도구 호출 (필수)
- **MAPPING** → `python3 "$COMPLIANCE_AI_HOME/tools/crossmap.py" lookup <ISMS코드>` 또는 `search <키워드>` 또는 `by-law <법령> --jo <N>`.
  결과의 법령 조항 중 `✅`는 검증됨, `⚠️`(고시/ISMS-P 조번호)는 답변에서 "미검증"으로 표기하고 가능하면 MCP로 재확인.
- **AMENDMENT** → `python3 "$COMPLIANCE_AI_HOME/tools/legalize.py" history <법령>` 로 개정일 확인 후
  `python3 "$COMPLIANCE_AI_HOME/tools/legalize.py" analyze <법령> --at <YYYY-MM-DD> --detail 5` 로 신설/삭제/개정 조문 구조를 받아
  "변경 요약 + 영향 통제항목(crossmap 역매핑) + 대응 체크리스트"로 가공한다.
  ⚠️ `analyze`는 **조(條) 단위**만 반환한다. 항(項)·호(號) 번호를 answer에 쓰려면 그 조문 원문을 실제로 조회한 뒤에만. analyze를 항 번호의 근거로 표기하지 말 것.
- **DIAGNOSIS** → `rag.py search`로 업로드 문서 관련 인증기준 원문(주요 확인사항·결함사례) 검색 + crossmap으로 통제 매칭 후 gap 정리.
- **인증기준 근거 인용 시**: RAG 결과는 출처·페이지(`source p.N`)를 함께 표기. RAG는 참고 검색이므로 규범적 단정은 원문(안내서) 확인 후.

### 🔎 RAG 검색 요령 (질의 확장)
`rag.py search`는 키워드(TF-IDF)+의미(로컬 임베딩) 하이브리드다. 그래도 사용자 표현과 문서 용어가 다르면 놓칠 수 있으므로 **질의를 그대로 한 번만 던지지 않는다.**
1. **원 질의** 그대로 1회.
2. **법정·인증기준 용어로 바꾼 질의 1~2개** 추가. 예: "로그 얼마나 보관" → "접속기록 보관 기간", "패스워드 정책" → "비밀번호 작성규칙", "CCTV" → "고정형 영상정보처리기기", "데이터 유출 알림" → "개인정보 유출 통지".
3. **질의들은 한 번의 호출에 모두 넘긴다** — `rag.py search "<원 질의>" "<법정용어 질의1>" "<질의2>" --collection <이름> -k 5`. 호출마다 임베딩 모델 로드에 약 10초가 들기 때문에 질의별로 따로 호출하지 않는다.
4. 결과를 합쳐 중복 제거 후 근거로 쓴다. 출력 헤더의 `[hybrid]`/`[tfidf]`로 어느 백엔드가 쓰였는지 확인 — `[tfidf]`면 임베딩 미설치·미인덱싱이라 2단계가 특히 중요.

### 📥 가이드/고시 자동 확보 루프 (관련 문서가 KB에 없을 때)
질의 관련 가이드라인·고시 해설서가 어느 컬렉션에도 없으면 직접 확보 후 답한다:
1. **검색** — 웹검색으로 공식 출처(개인정보위·KISA·금융보안원·법제처)의 **최신본** PDF를 찾는다.
   ⚠️ **반드시 최신 개정 반영본**인지 확인(예: 안전성확보조치는 2025-10-31 시행 개정 → 2025.11 안내서). 연도만 보고 옛 버전 넣지 말 것.
2. **확보** — `python3 "$COMPLIANCE_AI_HOME/tools/kb_add.py" <PDF_URL> --collection <이름> --name <파일명>` (다운로드+인그레스트 한 번에)
3. **검색·답변** — `python3 "$COMPLIANCE_AI_HOME/tools/rag.py" search "<질의>" --collection <이름> -k 5` 결과를 근거로 표준 골격 답변. 출처·페이지 표기.
4. 비공식 도메인 경고가 뜨면 원문 정본 여부를 확인하고, 규범적 단정은 신중히.

### ⏱ 시행일 처리 (필수)
- 법령 조회 시 **시행일 vs 오늘**을 반드시 구분한다. `legalize.py show`가 "⚠️ 시행예정본" 경고를 내면 그 버전은 **아직 현행이 아니다.**
- 시행 전 개정을 다룰 때: **결론 최상단에 "🔴 시행예정(YYYY-MM-DD 시행) — 현재 미적용" 배지**를 달고, 현재 의무는 현행본 기준으로 별도 서술. 현행본은 `legalize.py show <법령> --as-of <오늘>`로 조회.
- "금년도 개정 골자입니다"처럼 시행예정본을 현재완료형으로 단정하지 않는다.

### 🔒 환각 방지 (필수)
- **도구가 반환하지 않은 값(날짜·조·항·호·mst·수치)은 본문에 단정 금지.** 확인 안 한 값은 그 자리에 인라인으로 "(미확인)" 표기. 검증 섹션에서 몰아서 실토하는 것 금지 — 본문과 검증이 어긋나면 안 된다.
- **식별번호 노출 금지.** `mst`(법령일련번호)·`efYd`·`OC`·`admRulSeq` 같은 API 식별자는 **출력 어디에도 쓰지 않는다.** 근거·검증·출처·조회경로 **어느 칸에도** 넣지 말 것. "법령일련번호 283839", "MST 283839", "mst=283839", "(get_law_text, mst=283839)" 전부 금지.
  - 숫자는 배관용이다. 도구가 mst/efYd를 반환하면 그 응답의 **제목·시행일로 해석**해 인용한다.
    예: `mst=283839, efYd=20260911` → **"「개인정보 보호법」(2026-09-11 시행본, 공포 2026-03-10)"**
  - 출처를 밝힐 때는 **법령명 + 시행일**(필요시 공포일·개정번호)까지만. 조회 경로를 남기려면 도구 이름과 조문만: `legalize.py show 개인정보보호법 --jo 29` / `법령 MCP 조회`.
  - **답변을 내보내기 전 마지막 점검**: 본문에 `mst` `efYd` `OC` `admRulSeq` 또는 6자리 이상 정체불명 숫자가 있으면 지운다.

3. **계층 태깅** — 인용마다 계층 표시: `[법령]` `[행정규칙·고시]` `[인증기준]`.
   - **`L1`/`L2`/`L3` 같은 내부 약어는 출력에 쓰지 않는다.** 계층 구분은 내부 정리용이고, 답변에는 사람이 읽는 말로 쓴다.

4. **검증** — 인용 조문 번호·문구를 조회 원문과 대조. 불일치하면 답변에 넣지 않는다.

5. **표준 골격으로 출력** (아래).

## 출력 골격

```
## 결론
(핵심 1~3문장. 단정은 근거가 뒷받침될 때만)

## 근거
- **[법령] 법령명 제N조 제M항 제K호** "원문 인용…" — (법령명 + 시행일. 식별번호 금지)
- **[행정규칙·고시] 고시명 제N조** "원문 인용…" (시행 YYYY-MM-DD)

## 크로스 매핑        ← MAPPING/DIAGNOSIS일 때만
| 인증기준(ISMS-P) | 고시(안전성확보조치 등) | 법령 | 비고 |
|---|---|---|---|
| 2.6.1 … | 제5조 … | 개인정보보호법 제29조 | … |

## (개정 영향)        ← AMENDMENT일 때만
- 개정 전/후 조항 diff 요약, 영향 통제항목, 대응 체크리스트

## 검증
- 인용 조항 원문 대조: ✅ 완료 / ⚠️ 미검증(사유)
- 시행 상태: 🟢 현행(시행 YYYY-MM-DD) / 🔴 시행예정(YYYY-MM-DD) — 오늘 기준
- 기준 개정·시행일: YYYY-MM-DD

## 유의
본 답변은 참고용이며 법률 자문이 아닙니다. 실제 적용 전 최신 개정본과 소관기관 유권해석을 확인하세요.
```

## 금지사항
- 조문 번호/문구를 기억으로 지어내기
- **도구가 반환 안 한 날짜·조항·항·호·수치를 본문에 단정** (→ 인라인 "(미확인)")
- **본문 단정 ↔ 검증 섹션 불일치** (검증에서 "미확인"이면 본문에서도 단정 금지)
- **시행예정본을 현행처럼 서술** (시행일 > 오늘이면 "🔴 시행예정" 배지)
- **식별번호(mst=, efYd=, OC=) 노출** (→ 법령명+시행일로 해석. "법령일련번호 N"도 금지)
- 근거 없이 "~해야 한다" 단정
- 계층 혼동 (법령과 인증기준을 같은 근거로 뭉뚱그리기)
- **출력에 `L1`/`L2`/`L3` 약어 사용** (→ [법령] / [행정규칙·고시] / [인증기준])
- 개정일 누락 / 참고용 고지 누락
