# 범용 RAG (L3 지식베이스)

"아무 PDF/텍스트나 넣으면 지식베이스가 되는" 검색 계층. 법령 아닌 문서(L3: ISMS-P 안내서,
전자금융기반시설 점검항목, 금융보안원 가이드 등)를 컬렉션 단위로 흡수한다.

## 설계 — 키워드 + 의미 하이브리드
| 백엔드 | 구현 | 강점 | 필요 |
|---|---|---|---|
| 키워드 | 문자 n-gram(2·3) TF-IDF 코사인. 단 항목번호(`2.5.4`)는 쪼개지 않고 한 토큰으로 | 문서와 같은 단어·조문 제목·항목번호 질의 | 없음(순수 stdlib) |
| 의미 | 로컬 임베딩 **nlpai-lab/KURE-v1**(BGE-m3 한국어 추가학습) 코사인 | 바꿔 말한 질의("로그"↔"접속기록", "패스워드"↔"비밀번호") | `sentence-transformers` (선택) |
| 결합 | **가중 RRF** — 순위 r의 점수 `w/(60+r)`, 의미 w=1.0 · 키워드 w=0.25 | 조문번호 질의는 키워드가 보완 | — |

- **선택 의존성**: `sentence-transformers`가 없으면 ingest는 TF-IDF만 만들고, search `--mode auto`는 TF-IDF로 동작한다(기존과 동일).
- **임베딩은 로컬 계산**: 별도 임베딩 API(외부 업체·API 키·과금)가 필요 없고, 인덱싱 시 문서 전체를 다른 업체로 보내지 않는다. 모델이 캐시에 있으면 `rag.py` 자체는 네트워크에 접근하지 않는다(`local_files_only`).
  - ⚠️ **기밀 보호 수단은 아니다.** 검색 결과 청크와 Claude Code가 읽는 문서(P4 업로드 문서 포함)는 답변 생성을 위해 Anthropic API로 전송된다. 사내 문서를 넣을지는 조직의 생성형 AI 사용 정책·Anthropic 데이터 처리 조건으로 판단할 것.
- **결정적 해시**: `zlib.crc32` (내장 `hash()`는 프로세스별 랜덤 시드라 사용 불가 — 이 함정 주의).
- 인덱스는 컬렉션별 `data/kb/<name>/{chunks.jsonl, index.json, dense.npy}`. 원본·인덱스는 [.gitignore](../.gitignore)(대용량·재생성 가능).
- 모델 교체: `RAG_EMBED_MODEL` 환경변수 또는 `ingest --model`. 검색은 인덱스에 기록된 모델을 자동 사용.
- **기존 컬렉션은 재인그레스트해야** 의미검색이 켜진다(`list`에서 `임베딩 없음`이면 TF-IDF만).

## 사용
```bash
python3 -m pip install --user pypdf          # PDF 처리 시 1회
python3 tools/rag.py ingest <파일...> --collection isms   # 로컬 pdf/txt/md — 컬렉션을 새로 만듦(기존이면 덮어씀, 경고 출력)
python3 tools/rag.py ingest <파일...> --collection isms --append   # 기존 컬렉션에 추가(새 청크만 임베딩)
python3 tools/rag.py search "접속기록 보관 기간" --collection isms -k 5   # 기본 --mode auto
python3 tools/rag.py search "로그 보관 기간" "접속기록 보관" --collection isms   # 여러 질의 한 번에(모델 1회 로드)
python3 tools/rag.py search "2.5.4" --collection isms --mode tfidf          # 백엔드 강제(auto|hybrid|dense|tfidf)
python3 tools/rag.py show --collection isms --chunk 244            # 원문 전체(앞뒤 1청크 포함, --context N)
python3 tools/rag.py show --collection isms --page 146             # 페이지 원문(조문 단위 컬렉션은 --page 제29조 --source 개인정보보호법)
python3 tools/rag.py list
python3 tools/rag.py reindex --collection isms   # TF-IDF만 재생성(임베딩 유지) — 토큰화 규칙 변경 후
python3 tools/rag.py drop --collection isms
```
- HWP는 미지원 → 텍스트/PDF로 변환 후 투입.
- 임베딩 설치: `python3 -m pip install --user sentence-transformers` (torch 포함 약 3GB). 첫 ingest 때 모델 약 2GB 다운로드.
- **속도(CPU, 2026-11-11 측정)**
  - 인덱싱: 모델 로드 약 10초 + 임베딩 청크당 약 0.6초. 실측: ISMS-P 안내서 2023.11.23판(264쪽, 484청크) **약 7분**(다른 작업과 CPU 공유 상태). 문서 추가 시 1회성. `ingest`·`reindex`는 끝에 소요 시간을 출력한다.
  - `reindex`(TF-IDF만): 484청크 0.8초.
  - 검색: 호출마다 torch·모델 로드로 **약 11초 고정 비용** + 질의당 약 0.1초. 그래서 질의 여러 개는 한 호출에 넘긴다(`search "q1" "q2" "q3"` → 3개도 약 11초). TF-IDF 모드는 약 0.3초.
- **문서 추가 `--append`**: 기존 청크·임베딩은 그대로 두고 새 파일의 청크만 임베딩해 덧붙인다(PDF 1권 추가 비용 = 그 PDF 임베딩 시간만).
  - 같은 문서(확장자를 뺀 파일명이 같음)가 이미 있으면 그 문서의 청크만 교체(같은 파일을 두 번 넣거나 pdf→md로 다시 넣어도 중복되지 않음). 개정판은 파일명을 바꾸면 둘 다 남는다.
  - 기존 컬렉션과 다른 임베딩 모델(`--model`)이나 `--no-dense`로는 추가할 수 없다(임베딩이 섞이면 검색이 깨짐) — 전체 파일로 다시 `ingest`.
  - 기존 컬렉션이 TF-IDF 전용이면 추가분도 TF-IDF만. 의미검색을 켜려면 전체 파일로 다시 `ingest`.
  - 컬렉션이 없으면 새로 만든다.
- 검색 결과의 `(키워드 N위 · 의미 M위)`로 어느 백엔드가 찾았는지 확인할 수 있다.
- **검색 결과 → 답변 근거**: `search`는 청크 전문을 출력한다(사람이 훑어볼 때만 `--brief`로 앞 240자).
  청크는 800자 단위라 표·문장이 경계에서 잘릴 수 있으므로, 인용·숫자 확인은 `show`로 한다. `show`는 앞뒤 청크의 겹친 부분(150자)을 한 번만 이어 붙이고, 페이지가 바뀌면 `p.N`별로 나눠 출력한다.
  - 2026-11-11 이전에는 `search`가 청크 앞 240자(평균 청크의 약 40%)만 출력해, 예컨대 "접속기록 보관 기간" 검색에서 정답 페이지는 찾고도 보존 기간(1년/2년 이상)은 Claude에게 전달되지 않았다.
  - PDF를 바로 넣으면 옆면 탭 글자("1 관 리 체 계 …")·머리글이 청크에 섞인다 → 아래 `pdf2md.py`로 md 변환 후 넣는 것을 권장.

## PDF → Markdown 변환 후 인그레스트 (권장) — [tools/pdf2md.py](../tools/pdf2md.py)
```bash
python3 -m pip install --user docling                       # 1회. 표·레이아웃 모델은 첫 실행 시 다운로드
python3 tools/pdf2md.py data/kb_src/안내서.pdf               # → 안내서.md + 안내서.report.json(원문 대조)
python3 tools/rag.py ingest data/kb_src/안내서.md --collection isms
```
- **변환기 docling**(표 구조 인식, OCR 끔): 머리글·바닥글·옆면 탭 자동 제거, 표는 md 표로(병합 셀은 행마다 값 반복), 항목 머리말 상자(항목/인증기준/주요 확인사항/관련 법규)도 표로 정확히 변환.
  - 비교한 pymupdf4llm은 병합 셀 표의 값이 빠지고(보존기간 표에서 "5만명 이상" 행의 기간 공란) 항목 상자 제목·내용이 한 줄씩 밀려 채택하지 않음.
- **LLM으로 다시 쓰지 않는다**: 결정적 변환이라 같은 PDF는 같은 결과, 문장·숫자가 바뀌지 않는다(원문 인용 전제).
- **쪽 표시**: 페이지마다 `<!-- p.N -->`(원본 PDF 쪽 번호). `ingest`가 읽어 청크마다 쪽수를 기록한다.
- **원문 대조**: 변환 후 원본 PDF 텍스트(pypdf)와 페이지별 단어 대조. 여러 페이지에 반복되는 단어(머리글 등)·쪽번호는 제외. 결과는 `.report.json`, 누락 많은 페이지를 출력 — 사람이 확인할 곳을 기계가 고른다.
  - ISMS-P 안내서 2023.11.23판: 264쪽 **403초**, 본문 단어 37,383개 중 누락 51개(0.14%). 누락은 표지 로고, 그림 아래 "출처: KISA…"·그림 제목(p.35·131·158·176), 장 머리글, pypdf 쪽의 단어 분리 차이 — **인증기준 본문 누락 없음**. 단 그림 설명(출처·제목)은 md에 없다.
  - 알려진 한계: p.146 보존기간 표에서 두 조건 행이 한 행으로 합쳐짐(값은 둘 다 "최소 2년 이상"으로 정확).
- **표 셀 누락 경고**: docling(TableFormer)이 표 셀을 버리면 "N of M pdf cells … were dropped from the table" 경고를 남긴다(docling 주석상 '실제 내용 손실'). 쪽 번호가 없어서 `pdf2md`가 경고 난 20쪽 묶음만 한 쪽씩 다시 변환해 쪽을 특정하고,
  md의 그 쪽에 `<!-- warning: … -->`를 남긴다(.report.json의 `table_warnings`에도). `ingest`는 그 쪽 청크에 `warning`을 붙이고, `search`·`show`가 `⚠️ 표 구조 확인 필요`와 `show --page N --raw` 안내를 출력한다.
  `show --raw`는 `data/kb_src`의 같은 이름 PDF에서 그 쪽 텍스트(pypdf)를 함께 보여 준다 — 답변 시 Claude가 원본과 대조한다(스킬 규칙). 단어는 남고 위치만 틀어진 경우는 원문 대조(단어)로도, 이 경고로도 못 잡는다.
- **구조 단위 청킹**: md는 항목 머리말 표(`| 항 목 | 2.5.4 … |`)와 소제목(#)에서 자르고, 표·문단을 중간에서 자르지 않는다(긴 표는 행 단위로 나누고 머리행 반복). 청크는 쪽을 넘지 않는다.
  각 청크에 `section`(예: `2.9.4 로그 및 접속기록 관리 > 결함사례`)을 기록해 검색 인덱스 앞에 붙이고, `search`·`show` 출력에도 표시한다.
- 변환 md도 원본 PDF처럼 `data/kb_src/`(gitignore) — 각 기관 저작물.

## URL에서 바로 확보: kb_add ([tools/kb_add.py](../tools/kb_add.py))
웹에서 찾은 가이드/고시 PDF를 다운로드+인그레스트 한 번에. discover→ingest→answer 루프의 중간 단계.
기존 컬렉션에 **추가**한다(`ingest --append`) — 이미 들어 있는 문서는 유지된다. (2026-11-11 이전에는 컬렉션을 새 파일 하나로 덮어썼다.)
```bash
python3 tools/kb_add.py <PDF_URL> --collection sec_measures --name 안내서.pdf          # 다운로드 → md 변환 → 인그레스트
python3 tools/kb_add.py <PDF_URL> --collection sec_measures --name 안내서.pdf --no-md  # 변환 없이 PDF 그대로
```
- **PDF는 md로 변환 후 넣는다**(위 `pdf2md.py`). docling이 없으면 안내 후 PDF를 바로 넣는다.
- 변환 후 원문 대조 누락률이 1%를 넘으면 경고하고 확인할 페이지를 출력한다(인그레스트는 진행).
  - 짧은 문서(수 쪽)는 머리글·바닥글이 '반복 단어'로 걸러질 만큼 자주 나오지 않아 누락으로 잡힐 수 있다 — 출력된 단어를 보고 판단. (반복 단어 판정은 전체의 25% 초과 그리고 3쪽 초과. 하한이 없던 때는 3쪽 문서에서 대조 단어가 0개가 되어 검사가 사실상 생략됐다.)
- `--append`의 '같은 문서'는 **확장자를 뺀 파일명**이 같은 것. 예전에 `안내서.pdf`로 넣은 문서를 `안내서.md`로 다시 넣으면 교체된다(중복 없음).
- 공식 도메인(law.go.kr·kisa.or.kr·fsec.or.kr·pipc.go.kr·data.go.kr 등) 화이트리스트, 그 외는 경고.
- PDF 시그니처 검사(HTML 오류페이지 감지). 저장은 `data/kb_src/`(.gitignore).
- **버전 주의**: 최신 개정 반영본을 넣을 것. (예: 안전성확보조치 기준은 고시 제2026-9호(2026-07-01 일부개정) → **2026.11 안내서**. 2025.11·2024.10판은 옛 버전)
- **URL이 없는 게시판**: 개인정보위 등 게시판은 스크립트로 파일을 내려줘 `curl`로 받을 수 없다. 브라우저(Playwright MCP)로 받은 뒤 `file:///경로`를 `kb_add`에 넘긴다.

### 실증: 안전성 확보조치 기준 안내서 2026.11판 (2026-11-11)
1. 개인정보위 안내서 게시판(Playwright)에서 **"[현재 안내서] 개인정보의 안전성 확보조치 기준 안내서(2026.11.)"**(2026-11-05 게시, "고시 일부 개정(2026.7.1.) 사항 등을 반영") 확인 → 브라우저로 다운로드(204쪽, 3.4MB).
2. `kb_add file:///… --collection sec_measures` → md 변환 229초 · 원문 대조 누락 0.26% → 434청크 임베딩 4분 14초.
3. 원문에서 버전 확인: "[ 일부개정 2026. 7. 1. 개인정보보호위원회 고시 제2026-9호 ]", 부칙 "발령한 날부터 시행한다. **다만, 제15조제5호 및 제18조는 2027년 1월 1일부터 시행한다.**" → 이 두 조문은 2026-11-11 현재 **시행 전**.
4. 변환 확인 사항
   - p.96 "암호화 적용 기준 요약" 표: 값(행·열 대응)은 정확하나 표 제목이 셀에 섞이고 "저장 시" 묶음 표시가 다른 행에 붙음(docling이 셀 5개를 버렸다는 경고). 원문 대조가 이 페이지를 잡음 → 이를 계기로 위 '표 셀 누락 경고'를 자동화.
   - `<`·`>`·`&`가 `&lt;` 등으로 들어가던 문제(예: "부칙 &lt;제2026-9호…&gt;") → `pdf2md`에서 원문 문자로 복원하도록 수정.

### 실증: discover→ingest→answer (2026-07-16, 2025.11판 — 이후 2026.11판으로 대체)
1. 웹검색 → 개인정보 안전성 확보조치 기준 안내서 **2025.11**(2025-10-31 시행 개정 반영) 발견
2. `kb_add` → 3.9MB PDF, **318 청크** 인그레스트(collection `sec_measures`)
3. `rag search` → 제5조 접근권한 관리(3년 보관), **제6조의2 인터넷망 차단(2025 신설)** 원문 정확 추출
→ crossmap의 ⚠️ 안전성확보조치 조문 갭을 원문으로 보강.

위는 PDF를 바로 넣은 경우(현재 `isms_pdf`). **md 변환 + 구조 청킹(현재 `isms`, 546청크)**:

| 방식 | 바꿔 말한 질의(27) hit@1 / hit@5 / MRR | 항목명(6) hit@1 | 항목번호(4) hit@1 / hit@5 |
|---|---|---|---|
| TF-IDF | 56% / 89% / 0.66 | 100% | 100% / 100% |
| 의미(KURE-v1) 단독 | 85% / 96% / 0.90 | 100% | 0% / 50% |
| **하이브리드 w=0.25 + 번호 질의 라우팅 (기본)** | **81% / 96% / 0.87** | **100%** | **100% / 100%** |

- md 변환으로 바꿔 말한 질의 hit@1 74% → 81%, 번호 질의 25% → 100%(청크마다 `[2.5.4 비밀번호 관리]`가 붙어 키워드가 정확히 잡음).
- **번호 질의 라우팅**: 질의 전체가 점 구분 항목번호("2.5.4")면 키워드만 쓴다. 의미검색은 번호를 구별 못 해 목차 페이지를 올리고, RRF로 섞으면 키워드의 정답을 끌어내렸다(라우팅 전 hit@1 0%). 법률 조문번호("제48조의3")는 법률 세트에서 키워드 단독이 더 나빠 대상에서 뺐다.
- 의미 단독(85%)이 하이브리드(81%)보다 바꿔 말한 질의 hit@1이 1건 높지만 차이가 작고, 키워드를 빼면 항목명·용어 질의 안전망이 사라져 w=0.25 유지.

### 법률 원문
| 방식 | 바꿔 말한 질의(26) hit@1 / hit@5 / MRR | 조문 제목(6) hit@1 | 조문번호(6) hit@1 / hit@5 |
|---|---|---|---|
| TF-IDF | 12% / 35% / 0.21 | 100% | 0% / 50% |
| 의미(KURE-v1) 단독 | 54% / 92% / 0.72 | 100% | 33% / 67% |
| **하이브리드 w=0.25 (기본)** | **58% / 88% / 0.70** | **100%** | **50% / 83%** |
| 하이브리드 w=1.0 | 50% / 69% / 0.59 | 100% | 50% / 67% |

- 안내서는 법률보다 평이한 문장이라 TF-IDF도 꽤 찾지만(5위 내 85%), 의미검색으로 1위 적중이 +18%p. 법률에서는 TF-IDF가 바꿔 말한 질의를 거의 못 찾는다(5위 내 35%).
- 키워드를 동일 가중(w=1)으로 섞으면 두 세트 모두 바꿔 말한 질의가 나빠진다. **w=0.25가 두 세트에서 모두 최선이거나 동률** → 기본값.
- 의미검색 단독은 번호 질의("2.5.4")를 못 찾는다(0%) — 하이브리드에서 키워드가 보완. 번호 질의의 1위는 대개 목차 페이지(번호가 실제로 나열됨)라 hit@1은 낮고 정상이다. 번호로 항목을 찾을 때는 `crossmap.py isms <코드>`가 1차, RAG는 원문 상세용.
- **항목번호 토큰화 수정(2026-11-11)**: 예전엔 `.`을 지워 "2.5.4"가 "2","5","4"로 쪼개졌다(번호 질의 0%). 이제 `2_5_4` 한 토큰으로만 매칭(n-gram을 만들면 2.5.1·2.5.2와 조각이 겹쳐 목차가 이김). 기존 컬렉션은 `rag.py reindex --collection <이름>`으로 반영.
- **한계**: 유형별 질의가 4~27개라 1~2건 차이는 우연일 수 있다. 정답 페이지 범위는 항목 시작~다음 항목 시작 페이지(경계 페이지 포함)라 다소 관대하다. 모델 비교(예: `--model BAAI/bge-m3`)는 미실시.
