# legalize-kr 연동

법령 원문 + **Git 개정이력**을 로컬에서 활용하기 위한 연동. 개정영향 분석(P3)의 데이터·엔진 기반.

## 역할 분담 (MCP vs legalize-kr)
| 기능 | 담당 | 이유 |
|---|---|---|
| 실시간 법령/행정규칙 원문·조문 조회 | **korean-law MCP** | 최신 반영, 별표/서식, 판례까지 |
| 조문 개정이력·개정 diff (P3) | **legalize-kr** | Git commit = 개정 1건 구조, diff 즉시 |

## 설치
```bash
git clone https://github.com/legalize-kr/legalize-kr vendor/legalize-kr   # 약 677MB (전체 히스토리)
```
`vendor/legalize-kr/`는 [.gitignore](../.gitignore)로 제외(용량). 각자 clone.

## 최신본 자동 동기화
[tools/legalize.py](../tools/legalize.py)는 매 실행 시 원격(origin) 최신 여부를 확인하고 뒤처져 있으면 자동으로 맞춘다.
- 확인은 **하루 1회**로 제한(`.git/FETCH_HEAD` mtime 기준). 즉시 갱신은 `python3 tools/legalize.py sync`, 생략은 `--no-sync`.
- 업스트림이 이력 백필로 **force-push**되는 경우가 있어 pull 대신 `fetch + reset --hard`를 쓴다. 따라서 갱신 후 과거 커밋 해시가 달라질 수 있다(`history`/`diff` 결과의 해시를 영구 참조로 쓰지 말 것).
- vendor 저장소에 로컬 수정이 있으면 자동 동기화를 건너뛰고 경고만 낸다. 오프라인이면 경고 후 로컬본으로 진행.

## 저장소 구조
- 경로: `kr/{법령명}/{구분}.md` (법령명은 공백 제거, 예: `정보통신망이용촉진및정보보호등에관한법률`)
- 구분: `법률.md` / `시행령.md` / `시행규칙.md` (시행세칙·고시는 없음 → MCP 담당)
- Frontmatter(YAML): 제목·법령MST·법령ID·소관부처·공포일자·시행일자·상태·출처
- 본문: `##### 제N조 (제목)`, 조항 `**①**`, 개정마커 `<개정 YYYY.M.D>`
- 커밋: 1개 = 개정 1건, 커밋 날짜 = 공포일자, 메시지 = `법률: OOO (일부개정)`

## 헬퍼 CLI — [tools/legalize.py](../tools/legalize.py)
외부 의존 없음(Python stdlib + git).

```bash
python3 tools/legalize.py list                          # 대상 법률 + 시행일/상태
python3 tools/legalize.py show 개인정보보호법 --jo 21     # 특정 조문 원문 추출
python3 tools/legalize.py show 전자금융거래법 --kind 시행령
python3 tools/legalize.py history 개인정보보호법          # 개정이력(커밋=개정)
python3 tools/legalize.py diff 개인정보보호법 --at 2023-03-14   # 해당 개정 변경분
python3 tools/legalize.py diff 개인정보보호법             # 최근 두 개정 비교
```

기능: `list`(대상 목록) · `show`(법령/조문, frontmatter 시행일 포함) · `history`(개정 목록) · `diff`(개정 변경분).

## 시행본 선택 규칙 (`--as-of`, `_inforce_commit`)
어느 날짜에 시행 중인 본문 = **시행일 ≤ 그 날짜인 공포본 중 공포일이 가장 늦은 것**.
legalize-kr의 각 공포본은 그 이전 개정을 누적해 담기 때문이다(시행 전인 부분 포함).

- 2026-11-11 이전 규칙은 "시행일이 가장 늦은 것"이라, **나중에 공포됐지만 먼저 시행된 개정**을 놓쳤다.
  예) 신용정보법: 2026-03-10 공포(시행 09-11) 다음 2026-05-12 공포(시행 08-13, 제44조의2~5 신설).
  11-11 기준 옛 규칙은 03-10본을 골라 제44조의2가 없는 본문을 '현행'으로 냈다. 05-12본에 03-10 개정 내용이 누적돼 있음을 확인(03-10에서 추가된 줄 15/15).
  시행령의 "법 제44조의2" 참조를 대조하다 발견(docs/06-relations.md).
- 최신 공포본(작업 사본)이 이미 시행 중이면 이력을 뒤지지 않고 바로 쓴다(속도). 최신본이 시행 전(예: 개인정보보호법 2026-09-08 공포·2027-03-09 시행)일 때만 이력을 본다.
- 한계: 한 공포본 안에서 조문별로 시행일이 다른 경우(부칙의 "다만, 제N조는 …부터 시행")는 공포본 단위로는 구분할 수 없다 — 부칙을 확인할 것.
