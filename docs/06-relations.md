# 관계 추출 (인그레스트 시) — 그래프의 간선

헬퍼: [tools/relations.py](../tools/relations.py) · 결과: [data/relations/](../data/relations/) · 조회: `crossmap.py by-law`에 통합

## 왜 넣을 때 하나
RAG 검색은 상위 몇 개만 돌려준다. "항목 → 근거 법령"(정방향)은 답변 때 `rag.py show`로 그 항목의 "관련 법규" 칸을 읽으면 충분하지만,
**"이 조문이 바뀌면 영향받는 항목 전부"(역방향·전수, P3 개정 영향)**는 검색으로 빠짐없이 찾을 수 없다.
문서를 넣을 때 원문에 **명시적으로 적힌** 관계를 한 번 뽑아 두면 역방향 조회가 즉시·결정적이 된다.

- 사람이 정리하는 작업이 아니다. `rag.py ingest`가 쪽 표시 md를 넣을 때 맞는 추출기가 있으면 자동 실행한다(`extract_auto`).
- 관계가 원문에 적혀 있지 않은 문서(설명 위주)는 추출하지 않는다 — 검색용 청크만.
- 사내 통제 ↔ 인증기준처럼 **의미 판단**이 필요한 관계는 자동 추출 대상이 아니다(검수된 [crossmap.json](../data/crossmap.json)).

## 추출기
| 이름 | 판별 | 뽑는 관계 |
|---|---|---|
| `isms_related_laws` | 항목 머리말 표(`\| 항 목 \| 2.5.4 … \|`) + "관련 법규" 칸 | ISMS-P 항목 → 법령·고시 조문(조문 제목 포함) |
| `decree_delegation` | legalize-kr 대상 5법의 시행령(아래) | 시행령 조문 → 법률 조문(대통령령 위임·근거·참조) |

후보(같은 틀로 추가): 시행규칙 → 법률·시행령("법 제N조", "영 제N조"), 고시 부칙 시행일.

## 자동 대조(status)
뽑은 조문을 현행 원문의 조문 제목과 비교한다. **verified만 확인된 것**이고 나머지는 인용 전 원문 확인.

| status | 뜻 |
|---|---|
| `verified` | 현행 원문에 그 조문이 있고 제목이 같다(공백·가운뎃점 차이 무시) |
| `title_changed` | 조문은 있으나 제목이 다르다 — 안내서 발간 뒤 개정 가능성. 인용 시 현행 제목 사용 |
| `not_found` | 현행 원문에 그 조문이 없다(삭제·이동 가능성) |
| `no_source` | 대조할 원문이 로컬에 없다(대상 5법·안전성확보조치 기준 외) |
| `no_article` | 조문 없이 법령·지침 이름만 |

- **법령 원문**: legalize-kr의 **오늘 기준 시행본**(`legalize.py`의 시행본 선택 사용 — 시행예정본과 비교하지 않는다).
  대조 전에 `legalize.sync()`로 원격 최신 여부를 확인한다(24시간 지났으면 fetch, 오프라인이면 경고 후 로컬본). 결과 `_meta.legalize`에 대조한 커밋·마지막 원격 확인 시각을 남긴다.
- **고시 원문**: `data/kb_src`의 안전성 확보조치 기준 안내서(최신 파일명)에 실린 고시 전문. 안내서 PDF 변환 시 docling이 일부 조문 앞에 붙인 목록 번호("7. 제9조(…)")는 무시.

## 결과 (ISMS-P 인증기준 안내서 2023.11.23판, 2026-11-11)
항목 **73개 → 관계 176건**: verified 163 · title_changed 6 · no_article 5 · no_source 2. 추출+대조 약 20초.

- `title_changed` 6건 — 안내서(2023.11) 이후 조문 제목 개정으로 보임:
  - 개인정보보호법 제31조 "개인정보 보호책임자의 지정" → 현행 "…지정 등" (1.1.2, 1.3.3, 2.1.2)
  - 개인정보보호법 제34조 "개인정보의 유출 등의 통지·신고" → 현행 "개인정보 유출등의 통지ㆍ신고" (2.11.1, 2.11.5)
  - 정보통신망법 제50조 "광고성 정보 전송 제한" → 현행 "영리목적의 광고성 정보 전송 제한" (3.1.7)
- `no_article`: 개인정보 처리 방법에 관한 고시, 개인정보 영향평가에 관한 고시, 집적정보 통신시설 보호지침, 개인정보 국외 이전 운영 등에 관한 규정
- `no_source`: 소방시설법 제12조·제16조
- 역방향 예: **개인정보보호법 제29조 → ISMS-P 42개 항목**(검수된 crossmap은 8건).

### 수작업 crossmap과 대조
crossmap의 ISMS-P ↔ 개인정보보호법·안전성확보조치 기준 연결 15건은 모두 안내서 "관련 법규"와 일치.
안내서에 없는 6건(신용정보법 제19조, 위치정보법 제16조, 전자금융거래법 제21조, 정보통신망법 제45조)은 오류가 아니라
프로젝트가 "한 번 구현으로 다중 규제 충족"을 보이려고 넓힌 연결 — **근거가 안내서가 아니라 프로젝트 판단**임을 구분할 것.

### 이 작업으로 드러난 변환 문제 → 재발 감지
docling이 3.5.2 머리말을 `| 항 | 목 3.5.2 정보주체 권리보장 |`로 칸을 잘못 나눠 항목 인식에서 빠졌다 → 관계가 3.5.1로,
**RAG 청크의 항목 표시도 3.5.1로** 잘못 붙어 있었다. `ITEM_RE`를 이 변형까지 받도록 고치고 101개 항목 전부 인식 확인, `isms` 재인그레스트.

패턴 보완은 알려진 변형 하나만 막는다. 다른 모양으로 깨지면 또 조용히 빠지므로, **인그레스트 때 항목 정합성을 검사**한다(`check_items`, `relations.py check <md>`):
1. 번호 빈칸 — 같은 분야 안 1..최댓값(3.5.1 다음 3.5.3 → 3.5.2 누락, 확인할 쪽 범위 출력), 분야 번호도
2. '관련 법규' 칸이 한 항목에 2개 이상 — 다음 항목 머리말을 놓친 흔적
3. 기준 목록 — `data/isms_p.json` 영역별 항목 수(16/64/21)

고치기 전 패턴으로 돌리면 세 검사가 모두 3.5.2를 가리킨다(빈칸 3.5.2 p.250~259 사이, 3.5.1 칸 2개, 3영역 20/21). 현재는 0건.
발견되면 `kb-table-verify` 스킬이 해당 쪽 머리말 줄을 교정본으로 고쳐 `kb_fix.py`로 반영한다(칸 구분만 바뀌어 원본 단어 검사 통과 — p.253으로 `--check` 확인).
한계: 번호는 인식됐는데 항목명만 다른 칸으로 밀린 경우처럼 세 검사가 어긋나지 않는 손상은 못 잡는다.

## 시행령 → 법률 (decree_delegation)
법령은 RAG 문서가 아니라 legalize-kr 원문이라 '넣는 시점'이 다르다 — **legalize-kr가 바뀐 뒤 첫 조회 때** 자동으로 다시 추출한다
(`ensure_delegations`: 결과 파일의 legalize-kr 커밋이 현재와 다르면 재추출, 약 9초). 결과는 `data/relations/legalize_시행령_위임.json`.

- 대상: 대상 5법 시행령의 **오늘 기준 시행본** 본문(부칙 제외)의 `법 제N조[제M항]`. `같은 법 제N조`(다른 법률)는 제외.
- 같은 (시행령 조, 법률 조) 쌍은 하나로 묶고 언급 횟수·종류별 개수·항을 남긴다. 법률 조문이 오늘 기준 시행본에 있는지 대조.
- 분류(문장 패턴 **추정**, 같은 쌍의 언급 중 가장 강한 종류):
  - **대통령령 위임** — 같은 문장에 "대통령령으로 정하는"(예: `법 제25조제1항제6호에서 "대통령령으로 정하는 경우"란`)
  - **근거** — `법 제N조…에 따라/의하여` (예: 영 제30조 ← 법 제29조 안전조치의무: 법률이 "대통령령으로 정하는 바에 따라"라고 맡기고 시행령이 "법 제29조에 따라"로 받는 형태)
  - **참조** — 그 밖(업무 위탁 목록 등)
- 결과(2026-11-11): **692건, 전부 현행 법률 조문과 일치** — 대통령령 위임 169 · 근거 175 · 참조 348. 법률별: 개인정보보호법·신용정보법·정보통신망법·전자금융거래법·위치정보법.
- 이 작업 중 `legalize.py` 시행본 선택 버그 발견·수정(docs/03-legalize-integration.md): 처음 추출 때 신용정보법 시행령의 "법 제44조의2" 6건이 '현행 법률에 없음'으로 나왔는데, 옛 규칙이 05-12 공포본 대신 03-10 공포본을 '현행'으로 골랐기 때문. 수정 후 0건, 추출 136초 → 9초.

## 사용
```bash
python3 tools/crossmap.py by-law 개인정보보호법 --jo 29        # 검수된 통제 + 자동 추출 항목(전수) + 시행령 조문
python3 tools/relations.py by-item 2.9.4                       # 정방향
python3 tools/relations.py extract data/kb_src/<안내서>.md     # 수동 재추출(보통은 ingest가 자동)
python3 tools/relations.py list
```
- 결과 파일(`data/relations/*.json`)은 저장소에 포함한다 — 항목번호·조문번호·조문 제목 같은 사실 관계뿐이고, 원본 PDF가 없는 환경에서도 역방향 조회를 쓰기 위해.
- 안내서 새 판을 넣으면 다시 추출되므로, 이전 판 결과와 diff하면 "이번 개정에서 어느 항목의 관련 법규가 바뀌었나"가 보인다.
